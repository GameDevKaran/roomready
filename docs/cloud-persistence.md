# Durable receipt storage

RoomReady supports `ROOMREADY_STORE=sqlite` for its existing local persistent-volume setup and `ROOMREADY_STORE=gcs` for Cloud Run. The cloud adapter accepts only project `tough-melody-508008-p8` and bucket `tough-melody-508008-p8-roomready-sessions`. Attach a dedicated RoomReady runtime service identity with only the required object permissions on that bucket. Never reuse another application's identity, bucket or data. No credentials are bundled or sent to the browser.

Set `GCP_PROJECT_ID`, `ROOMREADY_GCS_BUCKET`, `ROOMREADY_STORE=gcs`, `NODE_ENV=production`, `HOST=0.0.0.0`, the runtime `PORT`, and the exact canonical `ROOMREADY_ORIGIN=https://…` with no trailing slash/path/query. Cloud Run startup refuses SQLite. Production refuses a noncanonical HTTPS origin. Keep `ROOMREADY_MODEL_PROVIDER=none` until approved actual Bedrock verification. Model usage is independent of this storage adapter.

Each opaque browser-owner hash maps to one JSON object containing the soundcheck, fixed expiry and operation hashes. Creation uses generation-zero preconditions; commands/deletion use generation-match preconditions. State and retry identity commit together. A lost response can be retried safely, and stale-session actions cannot mutate or delete a replacement. Data and its exact generation come from one Google Storage SDK media response; generations are never converted to JavaScript numbers. Reads fail closed on unreadable or oversized state. Provider failures return sanitized recoverable errors without erasing local browser state.

The original **absolute 24-hour expiry** remains unchanged. Activity, retries and service restarts do not renew it. Expired receipts cannot be read or changed; access attempts conditionally remove them. Configure a bucket lifecycle for eventual removal of abandoned objects as well. Lifecycle timing and object cleanup are not claims that physical deletion occurs at the exact expiry instant. Disable object versioning and soft delete if the deployment promises that a clear operation removes retained copies; otherwise accurately disclose retention. No lifecycle or bucket was created by this local milestone.

Objects are bounded to 1 MiB, while existing product limits still bound evidence and adjustments. HTTP admission allows 600 API/MCP requests per minute per process, per-owner limits remain 120/minute, and at most 1,000 new soundcheck attempts per UTC day per process. These reset on restart and are not financial caps or distributed quotas; use bounded service instances and the separately approved resource/cost scope. Existing receipts remain readable when new-soundcheck capacity is exhausted.

Tests cover concurrent bootstrap, state/CAS races, retry deduplication, lost responses, fixed expiry, deletion and expiry races with replacement, object limits, outages and real HTTP/MCP handling. A real pinned Google Storage SDK is exercised against a labelled local HTTP service, including generations larger than JavaScript's safe integer range, conditional writes/deletes and provider error mapping. **No live Google Cloud, Bedrock or microphone hardware verification is implied.**

Before marking deployed: record the actual URL, release commit/digest, dedicated identity/bucket configuration, public fresh-browser soundcheck, cookie/origin checks, genuine MCP actions, no raw-audio upload, durable persistence through instance/revision replacement, export/deletion and provider-failure behavior. A consenting supported-browser microphone capture/listening walkthrough remains required; synthetic audio tests cannot satisfy that hardware gate.
